# Reception Attendance scoped workflow (second patch)

Starting point: ff796b6. No deployment performed. No new SQL migration is required by this patch.

## Loader and route transitions

SessionProvider uses the current pathname and authenticated role. On /attendance for reception/admin it calls start(userId, 'attendance'); on /login it does not start the global store. Other role/route combinations keep the legacy full-store path. The provider prevents legacy screens from rendering a scoped store; navigating to Reports or Students loads the complete legacy dataset with its existing per-table completeness flags. Reception login now lands directly on Attendance, avoiding a legacy Dashboard bootstrap first. An unauthenticated /attendance entry preserves the fixed next=attendance intent through login for authorized staff. Admin default login and other-role homes remain unchanged; arbitrary next URLs are never accepted. Direct /attendance after authentication uses the scoped path. Real browser redirects have not been verified.

The scoped loader never starts fetchAll, sync_changes, snapshot restoration, financial table readers, or the 30-minute full sweep. It reads scheduling reference tables sequentially (500-row transport pages), the selected local calendar day of attendance, enrollment IDs for sessions on that weekday, then only the corresponding authorized students in 100-ID batches. Students include their complete nested enrollments. Already-attended students are included for corrections. Parent contact rows are fetched only for roster parent IDs. Teacher rows select ID and names, not pay fields. All queries use the existing caller-authenticated Supabase client/RLS. No service role is used. Schedule reference tables are still complete rather than session-by-session; these are not histories. Historical size is not a parameter of cold opening.

The day roster is deliberately incomplete school-wide: loaded remains false, complete.students=false, complete.attendance=false, and unrelated tables are explicitly incomplete. The student financial card in Attendance links to the legacy Students screen instead of embedding its full-school calculations against partial arrays. This is a visible workflow change: full ledger/recharge actions now require opening Students. The Attendance history tab explicitly requests the selected full date interval using server date predicates and stable ID transport pagination; it resolves missing student identities by ID. DOM pagination remains 100 rows. Period summary and printing consume every selected-period result, not just the visible page. Failed history reads show an error/retry and cannot print stale totals. A very large explicitly selected history interval can still be expensive; this patch does not implement server aggregate summaries.

## Confirmation and other desks

mark_attendance and scan_card RPCs are unchanged: the server owns billing and duplicate detection. After a successful scoped manual commit, two filtered readers fetch that student's row and their attendance on the marked date. This updates the roster balance and the day's attendance-derived totals without reading payroll/cash/balance history. A failed post-commit read keeps the successful result and flags local data failure; retry performs reads only, never repeats the payment RPC. RFID still publishes its returned balance immediately and starts its targeted read in the background.

The visible-desk timer/focus/online handlers now reload only this scope. It intentionally works without sync_changes, rereading the selected day and roster rather than using a global cursor. A second desk sees updates at the next visible 30-second tick, focus, or reconnect. Replacing the whole selected day handles deletes without deletion-log support. This is polling, not instantaneous push. It also reconciles enrollment changes for that day. Owner generations reject stale account/route reads, older bulk reads lose to confirmation invalidation, and same-student confirmations reject older reads. No partial scope is persisted in IndexedDB. Temporarily offline initial loads fail visibly; in-memory rows remain on later failed reads, with retry. Cold offline restore for Attendance is not provided.

Legacy historical absence-penalty reconciliation requires complete history and remains a legacy-screen operation. Scoped marking does not run that client-wide history sweep. The server billing RPCs are unchanged. Ensure the existing migration chain ends with 20261109_disable_absence_balance_deduction.sql, and reconcile historical contradicted penalties through the legacy complete-data workflow before rollout if they exist. Do not treat this scoped UI as a repair tool for old absence charges.

## Reproducible request evidence

`npx --no-install vitest run tests/attendance-workflow.test.ts --reporter=verbose`

The same synthetic database has one current-day student/session/enrollment, and 1,500 or 15,000 old attendance, balance and cash rows apiece. The test invokes the legacy fetchAll path and scoped start path, not the earlier CPU-filter benchmark. It logs table names, rows and request counts, never identities or row contents. Counts describe mocked PostgREST SELECT requests and top-level result rows (nested enrollment rows are not counted again); exclude public branding, auth/profile lookup, RPC roundtrips, headers and byte encoding. They are not browser HAR or production measurements. UUID partition decisions can add empty requests on legacy refresh, so use the emitted log for exact counts.

Cold scoped startup requests: sessions, subscriptions, classes, modules, teachers, salles, groups, free_periods; date-filtered attendance; subscription-filtered student_subscriptions; ID-filtered students. In this fixture: 11 SELECT requests / 4 returned rows at either size. Parent queries are absent because the fixture has no parent IDs. With real roster parents they are additional bounded ID queries. Cold legacy startup requests all 35 TABLES entries (see prior investigation), including payroll, balance_tx and cash_transactions. RPC cursor/branding reads are excluded from these counts.

Manual scoped save: 1 mark_attendance RPC plus 2 filtered SELECT requests / 2 returned rows, with or without sync_changes. Manual legacy fallback without sync_changes invokes full-table refresh. Tests emit exact before/after SELECT counts for both history sizes. No query is substituted with a trivial passing mock check: the fake executes filters, stable key order and transport pages, and the store maps returned records. However, the fake's billing/duplicate behavior models the server contract; it does **not** validate the deployed SQL transaction, RLS or concurrent database locking.

Assertions fail if cold startup or manual confirmation reads financial histories. Two independent store instances are open before the simulated commit; one marks and retries the same attendance, the other polls and sees exactly one attendance and balance 900 from 1000 at price 100. Deletion, failed post-commit read/retry, delayed read after account clear, >500-row selected-period history and full legacy financial transition are tested. Financial data completeness is verified at store level (all 1,500 ledger rows), not rendered reports/print-dialog output.

## Exact read-only Supabase check

Run scripts/check-attendance-sync.sql's first transaction in your Supabase SQL Editor. installed=false means the old sync migration is missing; no second function row is returned. installed=true means only the signature exists. respects_caller_rls must be true (SECURITY INVOKER); authenticated_can_call must be true. If either is false, investigate privileges/function definition rather than assuming sync works.

Then copy its commented second transaction, replace the test-user UUID and run under authenticated role as written. actual_school_role must be the intended reception/admin role. cursor_probe_tables must be 'object'; delta_tables_type must be 'object', server_cursor_present true, deletion_count a nonnegative count. Missing-function/permission/schema errors mean unusable sync. A successful probe does not prove all RLS row visibility or index efficiency. Repeat with an authorized test identity for each required role; never use a production user's JWT/key. Run scripts/diagnose-sync.sql for index/trigger/deletion/RLS metadata. No private payloads are output by these probes. New scoped Attendance does not require sync_changes; legacy screens retain the existing fallback.

For an old database apply schema.sql then all dated migrations in order, including 20261001_fast_sync_and_rls_speed.sql, 20261005_absences_friday_to_thursday.sql, 20261010_reduction_school_part_only.sql, and finally 20261109_disable_absence_balance_deduction.sql. Do not replay an older billing migration after November. No new migration/deployment ordering dependency is introduced. Old tabs retain their existing global sync protocol. Roll back by reverting this frontend commit; no SQL rollback.
